# Contributing

Thank you for contributing to **AI Ethics & Responsibility — Week 07**. This document outlines the process and expectations to keep collaboration smooth, professional, and aligned with the project's governance goals.

## How to contribute
1. Fork the repository and work in a feature branch named like: `feat/<short-description>` or `fix/<short-description>`.
2. Keep changes minimal and focused per pull request (one logical change per PR).
3. Write clear PR descriptions: explain _what_ you changed, _why_, and how to validate it.
4. Reference relevant issue numbers in the PR (e.g. `Fixes #12`).

## Code style & tests
- Python code: follow PEP8. Use `black` formatting if available.
- Add small unit tests where appropriate (e.g. for helper utilities).
- Keep dependencies minimal for prototype scripts.

## Documentation updates
- If you change behavior or add features, update the relevant docs in `/docs`.
- Add examples to `/examples` or notebooks under `/notebooks` for demonstrability.

## Review & CI
- All PRs should pass automated checks (see `.github/workflows`).
- Maintainers will perform code review and may request changes. Be responsive and iterate.

## Licensing and attribution
- Contributions will be accepted under the repository license (MIT).
- If you include third-party code/data, ensure the license is compatible and add attribution.

---

Thanks again — your contributions help make this work a robust, shareable resource for responsible AI adoption in software engineering.
